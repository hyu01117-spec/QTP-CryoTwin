# Cryo-floods 项目目录结构重构方案

> 目标：在**不改变技术栈、功能模块与业务逻辑**的前提下，按"功能/领域"重新划分目录，
> 消除层级混乱、命名不统一、职责边界模糊与死代码，并同步修正所有 import 与引用路径，
> 保证重构后项目可正常编译、构建、运行。
>
> 扫描基线：2026-08-31（仅扫描代码与配置，已排除 `data/`(85GB)、`大论文/`(738MB)、
> `.venv/`(1.9GB)、`webgis_backend/static`(2.7GB 运行产物)、`uploads/` 等数据/产物目录）。

## 二、存在的问题（附证据）

### 1. 职责边界模糊 —— `Training/input/` 名不副实、内容大杂烩
`input/` 实际装的是**代码**而非输入数据，内部 22 个脚本横跨 6 种职责且平铺混放：
- 训练：`train.py`、`evaluate.py`
- 推理：`predict.py`、`predict_streaming.py`(550行)、`run_era5_task.py`
- 预处理：`preprocess.py`、`preprocess_inference.py`、`fix_*.py`、`align_*.py`、`mask_*.py`
- 指标/特征：`flood_index.py`、`era5_index.py`
- benchmark：`bench_predict.py`
- 草稿/实验：中文名脚本 6 个 + 文件名含 `%` 的 1 个（`阈值场%.py`、`阈值场1p6.py` 等）

### 2. 命名不统一
- 后端/脚本用 `snake_case`，Training 大量用**中文描述性文件名且含空格**
  （`GEE 温度数据批量导出avg.py`——空格在 shell/git 中易出错）。
- 字面量 `%` 出现在文件名中（`阈值场%.py`、`阈值场grid_threshold_%.py`），属模板残留，易引发工具链异常。

### 3. 冗余 / 近重复代码
`Training/TibetanPlateau/dataget/` 中 GEE 导出与波段提取脚本按 avg/max/sum 机械枚举
（温度avg/max、降水max/sum、波段avg/max/sum……），属一次性数据获取脚本，可归并到 `acquisition/`。

### 4. 公共模块与业务代码混杂
`Training/input/sqlite2.py`、`创建sqlite_index.py` 是数据库 helper，却和业务脚本平级；
后端 `modules/utils.py` 是公共工具（被 5 个模块引用），划分合理，但 `admin.py` 直接
`from modules.llm import SYSTEM_PROMPT` 属跨域耦合，建议收敛到 `utils` 或保持现状（低风险）。

### 5. import 约定不一致 + 1 处坏引用（最高优先修复）
- 后端：`from config` / `from modules.x`（依赖"以 webgis_backend 为隐式包根、脚本方式运行"）。
- 测试：每个文件自行 `sys.path.insert(0, ROOT); sys.path.insert(0, webgis_backend)`，无 `conftest.py`。
- **坏引用**：`Training/input/run_era5_task.py:1` →
  `from webgis_backend.modules.meteorology.processor import ...`
  但 `webgis_backend/modules/meteorology/` **不存在**（全盘无此子包）。该脚本当前无法运行。
  （另一处 `Training/TibetanPlateau/dataget/阈值场grid_threshold_%.py` 仅含路径字符串，非 import，可保留。）

### 6. 层级 / 入口
- 根目录启动脚本、README、requirements 属正常入口，保留。
- `.idea/`、`.vscode/` 为编辑器配置，应加入 `.gitignore`（非删除）。
- `app.py` 中 `favicon()` 之后有一行被错误缩进的注释（`# 健康检查`），属无害但需清理的代码异味。

### 7. 已知关联问题（非本方案范围，顺带提示）
`webgis_backend/config.py` 指向 `data/raw/dem/wholeYarkant.tif`，该文件不存在
（实际 `web_dem.tif` 在 `data/processed/dem/`），属配置指向缺口，需另行修（见文末）。

## 四、各目录职责

| 目录 | 职责 |
|---|---|
| `webgis_backend/` | Flask 后端服务，按业务领域拆模块（modules/），对外提供 REST API 与页面路由 |
| `webgis_frontend/` | 浏览器端静态资源，由后端同源服务，无构建步骤 |
| `Training/acquisition/` | 从 GEE/本地源**获取并转换**原始栅格/矢量（导出、波段提取、坐标系/格式转换） |
| `Training/preprocessing/` | 训练/推理前的**栅格对齐、掩膜、CRS 修复、网格一致性**等预处理 |
| `Training/training/` | 模型**训练与评估**（train / evaluate） |
| `Training/inference/` | 模型**推理**与推理基准（predict / predict_streaming / bench_predict）；含需修的 run_era5_task |
| `Training/features/` | **特征/指标**构建（flood_index / era5_index） |
| `Training/extraction/` | 由原始数据**提取年最大值**等派生数据集（GLDAS 融雪、洪水、温度） |
| `Training/db/` | sqlite 索引/连接等**公共 DB helper** |
| `Training/scratch/` | 实验/草稿脚本归档，明确**不参与主流程**，降低误用风险 |
| `scripts/` | 跨模块工程脚本（数据预处理、性能基准） |
| `tests/` | 冒烟/并发/输出可读性/路由/径流引擎测试 |
| `docs/` | 技术思路、模块说明、评估汇报、论文规划、运维文档 |

## 六、执行顺序、风险点与验证方式

### Phase 0 — 安全网（必做）
- **动作**：确认 `git status` 干净；对当前状态做一次提交或打 tag，作为回滚点。
- **风险**：无。
- **验证**：`git status --short` 为空（或已提交）；`git tag refactor-before`。

### Phase 1 — Training 按领域重组（中风险，最大收益）
- **动作**：按 §5.1 建目录并 `git mv` 移动（用 git mv 保留历史）。
- **关键约束**：`predict_streaming.py` 与 `bench_predict.py` **保持同目录**（inference/），
  以维持 `bench_predict.py:31` 的裸 `from predict_streaming import ...`。
- **风险**：
  1. 脚本内部若用**相对路径/当前工作目录**定位数据，移动后可能找不到文件 → 需逐一核对路径解析。
  2. 含空格/中文/`%` 的文件名在 `git mv` 与 shell 中需引号包裹。
- **验证**：
  - `python -m py_compile $(find Training -name '*.py')` 全部通过；
  - 抽测 `python Training/inference/predict_streaming.py --help`、各预处理脚本可解析参数不报错；
  - `git diff --stat` 确认均为 `R`（重命名）而非误删；
  - 全局检索确认无残留对旧路径 `Training/input/...`、`TibetanPlateau/dataget/...` 的引用。

### Phase 2 — 后端 import 修整（中风险）
- **动作**：
  1. 新增 `webgis_backend/__init__.py`；
  2. 修复 `run_era5_task.py` 的 `webgis_backend.modules.meteorology.processor` 坏引用——
     先确认该符号现位于哪个模块（疑似已并入 `runoff_engine` 或 `snowmelt_flood`），
     **由你确认目标后再改**；若脚本已废弃则移入 `scratch/` 并标注。
  3. 清理 `app.py` 缩进注释。
- **风险**：
  - 加 `__init__.py` 后若某处依赖"以脚本方式运行"的隐式路径，行为可能变化 → 必须实跑验证。
  - 坏引用修复若指向错误模块，会引入新的运行时异常。
- **验证**：
  - `python -c "import webgis_backend.app"` 成功；
  - `python webgis_backend/app.py` 启动后 `curl /api/health` 返回 `{"status":"ok"}`；
  - `python -m py_compile webgis_backend/*.py webgis_backend/modules/*.py` 通过。

### Phase 3 — 测试与依赖一致性（低风险）
- **动作**：新增根 `conftest.py`（将 `webgis_backend` 与项目根加入 `sys.path`）；
  新增 `pyproject.toml`（`[tool.pytest.ini_options] pythonpath = ["."]`）；
  测试文件中的 `sys.path.insert(...)` 可保留（带 `# noqa`）或删除。
- **风险**：低；若 `conftest.py` 路径注入与既有逻辑冲突，测试会集体失败。
- **验证**：在项目根执行 `pytest tests/ -q`，全部通过（含 `test_route_smoke`、`test_runoff_engine`）。

### Phase 4 — 前端轻量整理（可选，中风险，默认不做）
- **动作（可选）**：将 `js/lib/*`、`css/lib/*` 迁至 `js/vendor/`、`css/vendor/`，
  并同步更新 7 个 html 中的 `src/href`。**不引入构建系统**（保持技术栈不变）。
- **风险**：html 引用路径多，漏改任一即前端 404；无构建无类型检查，只能靠页面实测。
- **验证**：启动后端，浏览器逐一打开 7 个页面，DevTools Console/Network 无 404（js/css）。

### Phase 5 — 根目录与 .gitignore（低风险）
- **动作**：`.gitignore` 追加 `.idea/`、`.vscode/`；删除临时脚本 `.workbuddy/scan_project.py`（本轮遗留）。
- **风险**：无。
- **验证**：`git status` 不再追踪编辑器目录；`git check-ignore .idea` 命中。

## 七、约束遵循说明
- **技术栈不变**：Flask + 静态前端 + 原生 Python 训练脚本，无新增框架/构建工具。
- **功能模块不变**：后端 19 个领域模块零重组；前端页面与接口不变；Training 仅移位不重写逻辑。
- **按领域划分**：Training 由"平铺的输入目录"转为 acquisition/preprocessing/training/inference/features/extraction/db/scratch 八大领域。
- **import 同步**：Training 内部唯一跨文件 import（`bench_predict→predict_streaming`）因同目录移动而**无需改写**；后端仅修 1 处坏引用并补 `__init__.py`；测试改用 `conftest.py` 统一注入，消除各自 `sys.path` hack。
- **可运行性**：每阶段均有启动/编译/测试验证，Phase 0 提供回滚点。
