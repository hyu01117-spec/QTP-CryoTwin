# 冰冻圈灾害数字孪生系统 · 前端交互与视觉优化审查清单

> 审查对象：`webgis_frontend/`（纯 HTML/CSS/JS，由 Flask 提供静态资源）
> 审查范围：交互动效、按钮、弹窗、下拉框、输入框、字体层级、布局间距/响应式、色彩规范
> 审查方法：静态代码走查（`styles.css` 4789 行、`components.css` 583 行、`js/*.js` 共 10872 行）+ 设计系统对照
> 结论：**基础组件库（components.css / ui-components.js）已较成熟**，问题集中在「色彩变量未分层、表单态缺失、组件体系不统一、可访问性/动效降级未做、布局响应式断点零散」。本清单给出的优化项均可落地，并尽量复用成熟开源实现（Ant Design / Element Plus / Framer Motion / Radix / Headless UI / Tom Select），避免重复造轮子。

## A. 前端色彩样式优化（统一色彩变量规范）

### A-1 建立分层设计令牌（Design Tokens），而非散落的十六进制
**现状**：`styles.css:3-46` 已定义一版变量，但存在三类问题：① 语义不分层（既有 `--primary` 又有 `--accent-color` 还有组件里直接写死的 `#3b82f6`/`#2563eb`）；② 状态色分散在 `components.css`（按钮里写死 `#ef4444`/`#10b981`）与 `:root`（`--danger-color` 等）两处，易漂移；③ 阴影/发光等值未变量化。
**目标效果**：一套可在全站引用、支持明暗双主题、语义清晰的色彩变量。所有组件不再写死色值。
**适用场景**：全局所有页面、组件、状态色、动效发光。
**推荐复用**：对标 **Ant Design 5 的 `theme.token`** 与 **Element Plus 的 CSS 变量体系**（`--el-color-primary` 派生 `--el-color-primary-light-3/5/7/9` 的算法）。可直接用 Ant Design 的「主色按 10% 阶梯派生」算法用 Sass/Less 函数批量生成 `primary-light-3` 等变量。
**落地改动**：将 `:root` 重构为分层结构（参见随附文件 `design-tokens.css`）：
- 基础层 `--color-blue-50…900`（调色板，仅此处写死）
- 语义层 `--c-primary / --c-primary-hover / --c-primary-active / --c-primary-light-3~9`
- 表面层 `--c-bg / --c-surface-1 / --c-surface-2 / --c-border / --c-border-strong`
- 文本层 `--c-text-1 / --c-text-2 / --c-text-3 / --c-text-inverse`
- 状态层 `--c-success / --c-warning / --c-danger / --c-info`（与各状态 light/dark 变体）
- 动效层 `--shadow-1/2/3`、`--glow-primary`、`--radius-sm/md/lg`、`--z-modal/overlay/toast`
- 并新增 `[data-theme="light"]` 覆盖层，预留浅色主题切换能力。

### A-2 补全「主色派生阶梯」变量并统一发光/阴影
**现状**：`--primary-glow` / `--ice-glow` 写死单值，hover/danger/success 仍是硬编码色值（如 `components.css:87` `#ef4444`、`#b91c1c`）。
**目标效果**：hover/active 态由派生变量自动计算，按钮、徽章、进度条全部引用语义变量。
**适用场景**：所有带交互的彩色元素。
**推荐复用**：Element Plus 的 `mix(color, white, 20%)` / `mix(color, black, 10%)` 派生算法（其 `theme/mix.ts` 可照搬）。
**落地改动**：在 `design-tokens.css` 中用 `@function` 生成 `--c-primary-hover = mix(primary, white, 12%)`、`--c-primary-active = mix(primary, black, 8%)`，并让 `.ui-btn-primary:hover` 改引用 `--c-primary-hover`。

### A-3 统一「危险/成功/警告」语义色到一处
**现状**：同一语义色出现在两处（`--danger-color` 在 `:root`，`#ef4444` 在按钮/徽章/进度条里）。
**目标效果**：单一事实来源，组件只引用 `--c-danger` 等。
**适用场景**：全局。
**落地改动**：删除 `components.css` 中按钮的硬编码状态色，全部改为 `var(--c-danger)` 等；保留 `--accent-color` 作为「强调青」语义（与 info/primary 区分）。

### A-4 流行配色方案对照（供选型参考）
**目标效果**：在现有冰蓝主题基础上，确认配色是否达到「监测大屏」工业级观感。
**推荐复用**：
- **Ant Design 5 默认蓝**（`#1677ff`，比现有 `#3b82f6` 更沉稳，适合数据密集场景）；
- **IBM Carbon** 的灰度阶梯（用于表面层，可读性更好）；
- **Radix Colors / Tailwind CSS 调色板**（提供经过对比度校验的 50–900 阶梯，建议直接借用其 `sky/blue` 阶梯值，避免自调踩坑对比度）。
**落地改动**：可将 `--primary` 由 `#3b82f6` 微调为更偏「数据蓝」的 `#2563eb`/`#1d4ed8` 家族（仅改一处变量即可全站生效）。

## B. 交互动效（过渡 / 加载 / 悬停）

### B-1 引入统一的动效时长与缓动令牌
**现状**：过渡时长散落（`0.18s`/`0.22s`/`0.25s`/`0.3s`），缓动函数不统一（`ease`/`cubic-bezier(0.4,0,0.2,1)`）。
**目标效果**：`--motion-duration-fast/normal/slow` + `--motion-ease-standard`（= Material `cubic-bezier(0.2,0,0,1)`）、`--motion-ease-emphasized`。全站过渡引用令牌，调风格只改一处。
**适用场景**：所有过渡动画。
**推荐复用**：**Material Design 3 的 Motion 规范** + Ant Design `motion` 变量命名。
**落地改动**：在 `design-tokens.css` 定义令牌，并批量替换 `components.css`/`styles.css` 中的散落时长。

### B-2 增加 `prefers-reduced-motion` 降级（可访问性必做）
**现状**：全站动画**无** reduced-motion 适配（已确认 `grep` 结果为 0 处）。
**目标效果**：用户开启「减少动态效果」系统偏好时，关闭非必要旋转/平移/闪烁（spinner 可保留但减速），避免前庭功能障碍用户不适。
**适用场景**：所有页面，尤其全屏加载、Toast、卡片 hover、骨架屏 shimmer。
**推荐复用**：**WCAG 2.1 SC 2.3.3 / 2.2.2**；参考 GitHub、Ant Design 的 reduced-motion 处理。
**落地改动**：在 `components.css` 末尾增加：
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .001ms !important;
    scroll-behavior: auto !important;
  }
}
```

### B-3 统一并收敛加载动画（消除重复实现）
**现状**：加载动画出现至少 4 套——全屏 `loading-spinner`（双环）、按钮级 `loading-btn`、`ui-btn.loading`（组件库）、表格 `loading-row`，且按钮级存在 `.loading-btn`（styles.css:2266）与 `.ui-btn.loading`（components.css:128）两套。
**目标效果**：统一为「一套全屏加载 + 一套按钮内联 spinner + 一套骨架屏」，避免同一语义多套实现导致观感不一致。
**适用场景**：数据请求、提交、表格刷新。
**推荐复用**：**Ant Design 的 `Spin`**（双环 border spinner，与现有 `loading-spinner` 一致，可直接沿用其尺寸/线宽规范）；按钮 loading 用 **Element Plus 的 `is-loading`** 态（图标替换文字）模式。
**落地改动**：删除 `styles.css` 的 `.loading-btn`，让所有按钮统一使用 `components.css` 的 `.ui-btn.loading`；将 `ui-spin` / `spin` 两个同义 keyframes 合并为一个。

### B-4 悬停反馈统一与「微交互」增强
**现状**：卡片/统计卡 hover 已有 `translateY(-2px)` + 发光（良好）；但 `.btn-small`、`.simulate-widget .btn`、导航 `a` 的 hover 态不一致。
**目标效果**：所有可点击元素 hover 有统一反馈（亮度/位移/边框三选一，且全站一致），并补充 `:active` 按压回弹（现仅 `.ui-btn` 有 `scale(0.98)`）。
**适用场景**：按钮、卡片、列表项、导航项。
**推荐复用**：**Ant Design 的 hover/active token**（`controlHoverBg`、`controlActiveBg`）+ Framer Motion 的 `whileTap={{ scale: 0.98 }}` 思路（若后续上框架）。
**落地改动**：为 `.btn-small` / 导航链接 / 统计卡补 `:active { transform: scale(0.98) }`；统一卡片 hover 位移为 `--motion-...` 令牌。

### B-5 骨架屏接入真实加载流（替代纯全屏 spinner）
**现状**：已有 `.ui-skeleton` 与 shimmer keyframes，但**经 `grep` 确认 HTML/JS 中无任何调用**（死代码），实际加载走全屏 `loading-spinner`。
**目标效果**：列表/统计区先用骨架屏占位，数据到达后淡入替换，避免整页「白屏转圈」。
**适用场景**：首页统计卡、查询结果表格、专家咨询列表。
**推荐复用**：**Ant Design `Skeleton`** 组件结构（多行占位 + 头像/卡片占位）。
**落地改动**：在 `query.js`/`admin.js` 的数据渲染前插入 `ui-skeleton` 占位，渲染后 `ui-fade-in` 淡入；删除未使用的 `.ui-skeleton` 或正式接上（二选一，不要留死代码）。

### B-6 入场动画的编排（staggered fade-in）
**现状**：个别元素有 `ui-fade-in`/`llm-msg-in`，但无「错峰入场」编排，卡片同时出现略显生硬。
**目标效果**：列表/卡片组按 `index * 60ms` 错峰淡入上浮，提升大屏「数据浮现」质感。
**适用场景**：统计卡网格、图层列表、结果卡片。
**推荐复用**：**Framer Motion 的 `staggerChildren`** 思路；纯 CSS 可用 `:nth-child` 递增 `--delay` 变量实现。
**落地改动**：为 `.ui-stat-grid > *`、`.layer-item` 加 `animation-delay: calc(var(--i) * 60ms)`，JS 渲染时写入 `--i`。

## C. 按钮样式与交互反馈

### C-1 收敛到「一套按钮体系」（消除三套并存）
**现状**：项目里并存 **三套** 按钮写法：① 组件库 `.ui-btn`（含 primary/ice/danger/success/ghost + sm/lg/block + loading）；② Bootstrap `.btn .btn-primary`（`bootstrap-buttons.min.css`，仅 alert.html/simulate.html 引入）；③ 局部 `.simulate-widget .btn`（手写，含 ripple）。选型不统一。
**目标效果**：全站统一使用 `.ui-btn` 体系；`alert.html`/`simulate.html` 的 `btn btn-primary` 改为 `ui-btn ui-btn-primary`；删除 Bootstrap 按钮样式依赖（仅保留其无关部分，或直接去掉该 css 引用）。
**适用场景**：全局所有按钮。
**推荐复用**：**Ant Design `Button` 的 variant/size/loading/disabled 矩阵**；`.ui-btn` 已贴近，只需补齐并统一。
**落地改动**：新增「危险次按钮/文字按钮/链接按钮」等变体以覆盖 Bootstrap 原有用法；将 `bootstrap-buttons.min.css` 从 HTML 移除。

### C-2 补齐按钮「加载/禁用/成功」反馈态
**现状**：`.ui-btn.loading`（✓ 良好）、`[disabled]`（✓ 有）；但缺少「点击成功后的对勾反馈」「禁用态说明」与「loading 时禁止重复提交」的统一封装。
**目标效果**：提交类按钮点击后自动进入 loading 并禁用，成功回调后短暂显示对勾再恢复；禁用态需有明确视觉区分（现 `opacity:.55` 偏弱）。
**适用场景**：所有表单提交、分析/模拟触发按钮。
**推荐复用**：**Element Plus `el-button` 的 `loading`/`disabled`** 行为。
**落地改动**：在 `ui-components.js` 提供 `UI.withLoading(btnEl, asyncFn)` 工具，统一处理 loading+disabled+恢复。

### C-3 按钮焦点态（键盘可达性）
**现状**：按钮无 `:focus-visible` 态（已确认 `grep` 全站 0 处 focus-visible）。鼠标用户无感，但键盘 Tab 用户无法分辨当前焦点。
**目标效果**：键盘聚焦时显示统一焦点环（offset ring），鼠标点击不显示。
**适用场景**：所有按钮、链接、控件。
**推荐复用**：**`:focus-visible` 伪类**（现代浏览器原生，无需库）；Ant Design 焦点环规范。
**落地改动**：增加通用规则：
```css
.ui-btn:focus-visible, a:focus-visible, .dropdown-toggle:focus-visible {
  outline: 2px solid var(--c-primary);
  outline-offset: 2px;
}
```

## D. 弹窗的显示/关闭逻辑及视觉表现

### D-1 弹窗补「焦点陷阱 + 滚动锁 + aria」
**现状**：`ui-components.js` 的 `modal()` 已支持 Esc/点遮罩关闭、有 `role="dialog"`，但**缺少**：① 打开时锁定 `body` 滚动；② 焦点陷阱（Tab 不逃出弹窗）；③ `aria-modal="true"` 与初始焦点定位；④ 关闭后焦点归还触发元素。
**目标效果**：打开弹窗时背景不可滚动、键盘焦点被限制在弹窗内、关闭后焦点回到原按钮，符合 ARIA Dialog 模式。
**适用场景**：所有 `UI.modal/alert/confirm`。
**推荐复用**：**Radix Dialog** 或 **Headless UI Dialog**（其焦点陷阱/滚动锁实现经过充分验证，可借鉴其算法，或评估直接引入 Headless UI 的 headless 逻辑）。
**落地改动**：在 `modal()` 中：打开时 `document.body.style.overflow='hidden'` 并记录 `lastFocused`；监听 `keydown` 实现 Tab 焦点循环；关闭时还原滚动与焦点、加 `aria-modal`。

### D-2 弹窗宽度自适应与移动端全屏化
**现状**：`.ui-modal` 固定 `width:420px` + `max-width: calc(100vw - 40px)`，移动端仍居中卡片，未考虑「底部抽屉 / 全屏」体验。
**目标效果**：窄屏（≤480px）弹窗转为接近全屏的底部上滑卡片（bottom sheet），更符合移动端习惯。
**适用场景**：手机/平板上查看详情、确认操作。
**推荐复用**：**Ant Design `Modal` 的 `width` 响应式** + Material Bottom Sheet。
**落地改动**：加 `@media (max-width:480px){ .ui-modal{ width:100%; max-width:100%; border-radius:16px 16px 0 0; align-self:flex-end; } }` 并让 overlay 用 `align-items:flex-end`。

### D-3 弹窗内容区支持富文本/表单/滚动
**现状**：`ui-modal-body` 仅 `textContent`，无法放表单、长列表或图片；长内容无内部滚动。
**目标效果**：`message` 支持传入 DOM 节点/HTML 片段；长内容内部滚动（`max-height + overflow:auto`），footer 固定。
**适用场景**：风险评估详情、专家咨询结果、表单型弹窗。
**推荐复用**：**Ant Design `Modal` 的 `content` slot** 模式。
**落地改动**：`modal()` 的 `message` 支持 `Node | string`；`.ui-modal-body{ max-height:60vh; overflow:auto }`。

### D-4 统一确认弹窗的「危险操作」视觉警示
**现状**：`confirmDialog` 的 `danger` 仅切换按钮为 `ui-btn-danger`，正文无警示图标/红色强调。
**目标效果**：删除/重置等危险操作，弹窗标题带红色警示图标、正文首句高亮，降低误操作。
**适用场景**：管理后台删除、重置、批量操作。
**推荐复用**：**Ant Design `Modal.confirm` 的 `warning/error` 类型**。
**落地改动**：`confirmDialog({ danger:true })` 时自动加 `fa-exclamation-triangle` + 正文 `.ui-modal-body.danger` 红色强调样式。

## E. 下拉框的选中与展开体验

### E-1 收敛到「两套下拉」并补齐键盘可达性
**现状**：下拉存在 **三类**——① 顶部导航 `dropdown-menu`（hover/click 展开，箭头旋转 ✓）；② 页面内 `es-select`（自定义，含 `.selected` 对勾、分组）；③ Tom Select（流域/模型，搜索型）。其中 `es-select` 的 CSS 完整但**经 `grep` 确认无任何 HTML/JS 调用（死代码）**；导航下拉的展开/收起依赖 `admin.js` 的 click 处理。
**目标效果**：保留「导航 dropdown」+「Tom Select 搜索下拉」两套即可；删除死代码 `es-select` 或正式接线。下拉均支持 **方向键导航 + 回车选中 + Esc 关闭 + 键盘可达**。
**适用场景**：导航菜单、表单选择、流域/模型选择。
**推荐复用**：**Tom Select**（已有）覆盖搜索型；非搜索型可考虑 **Radix Select / Headless UI Listbox** 以获得键盘与 ARIA 支持，避免自写下拉的无数坑（点击外部关闭、滚动定位、虚拟列表）。
**落地改动**：`es-select` 死代码删除或接 admin 表单；为导航 `dropdown-menu` 加键盘事件（已具备 Esc 关闭雏形，补 ↑↓/Enter）。

### E-2 下拉展开动画与定位一致性
**现状**：导航 `dropdown-menu` 有 `scale(0.98)→1` + 箭头旋转（良好）；但 `.es-select` 的菜单是 `translateY(-4px)+opacity` 且 `z-index:50` 偏低，可能被侧边面板（z:30）或地图控件遮挡。
**目标效果**：统一展开动效（y 位移 + 透明度 + 轻微 scale），并统一 z-index 到 `--z-dropdown` 令牌（建议 ≥ 1000，高于面板但低于弹窗）。
**适用场景**：所有下拉。
**推荐复用**：**Ant Design `Dropdown` 的 `placement` + motion** 规范。
**落地改动**：`es-select` 的 `z-index:50` 提到 `--z-dropdown`；统一 transform 起点。

### E-3 选中态视觉强化（对勾 + 高亮）
**现状**：Tom Select 选中态、`.es-option.selected` 有对勾（✓）；但导航 `dropdown-item.active` 仅左侧色条，无文字确认感。
**目标效果**：选中项有清晰「当前值」标识（对勾 / 文字色 / 左侧条三者统一其一），与 hover 态明显区分（hover 浅底、选中 实底色或强文字色）。
**适用场景**：所有单选下拉。
**推荐复用**：**Element Plus `el-select` 选中项** 表现。
**落地改动**：统一 `.selected`/`.active` 表现，避免 hover 与选中视觉混淆。

## F. 输入框的聚焦状态与校验提示

### F-1 统一输入框聚焦环（深浅一致）
**现状**：多处输入框 focus 是 `box-shadow: 0 0 0 3px var(--primary-glow)`（components.css:568）或 `0 0 5px`（simulate-widget），线宽/发光不一致；且无 `--c-primary-light-9` 那种淡底聚焦态。
**目标效果**：所有输入框聚焦时用统一「2px 主色边框 + 外发光环 + 极淡主色底」三件套，线宽改为 `--ring-width` 令牌。
**适用场景**：登录、搜索、表单、日期选择。
**推荐复用**：**Ant Design `Input` focus 态**（`box-shadow: 0 0 0 2px rgba(primary,0.1)` + 边框主色）。
**落地改动**：抽取 `.ui-input` 现有实现为全站唯一输入框类（见 F-3），统一 focus 样式。

### F-2 表单校验提示体系（当前完全缺失）
**现状**：`grep` 确认全站**无任何** `:invalid`/`is-invalid`/`error-message`/校验文案实现；表单仅做 JS 层面的 `if (valid) ... else showAlert(...)`，错误以 Toast 抛出，用户需回看表单找字段。
**目标效果**：字段级实时校验——错误态红框 + 下方红色文案 + 图标；正确态可显示对勾；失焦（blur）触发、提交时汇总。
**适用场景**：登录、分析参数、模拟配置、管理后台表单。
**推荐复用**：**Ant Design `Form` + `Form.Item` 的 `validateStatus`/`help`**；或 **React Hook Form + Zod**（若上框架）。纯原生可借鉴其「`has-error` 容器 + `.error-text` 提示」DOM 结构。
**落地改动**：提供 `UI.validateField(inputEl, rule)` 工具：加 `.is-invalid`/`.is-valid` 类 + 渲染 `<span class="ui-field-error">`。CSS 增加：
```css
.ui-input.is-invalid { border-color: var(--c-danger); box-shadow: 0 0 0 3px var(--c-danger-light-9); }
.ui-field-error { color: var(--c-danger); font-size: 12px; margin-top: 4px; }
```

### F-3 输入框类统一（`.ui-input/.ui-select` 当前为死代码）
**现状**：`components.css:551` 定义了 `.ui-input/.ui-select`，但**经 `grep` 确认 HTML/JS 无任何引用**；实际输入框散落在 `alert-form-group`/`query-widget`/`simulate-widget` 各自的类里，聚焦/圆角/字号各自为政。
**目标效果**：表单统一使用 `.ui-input/.ui-select`（已写好），其余局部样式逐步迁移或 `@extend` 复用，消除重复。
**适用场景**：全部表单。
**推荐复用**：**Element Plus `el-input` 尺寸/suffix/前缀** 结构。
**落地改动**：新表单直接用 `.ui-input`；旧表单在 `styles.css` 对应类里 `@extend` 或合并到 `.ui-input` 规则。

## G. 字体选择与字号层级规范

### G-1 固定字体层级（Type Scale）并消除散落字号
**现状**：`styles.css` 中 `font-size` 出现 100+ 处且数值离散（12/13/14/15/16/18/20/24/28px 混用），无统一阶梯；标题用 `font-display`（Chakra Petch），正文用 Noto Sans SC（✓ 方向正确）。
**目标效果**：建立 `--fs-xxx` 阶梯（如 `-1:12 / 0:13 / 1:14 / 2:16 / 3:20 / 4:24 / 5:28 / 6:32px`），并定义 `--lh-tight/normal/loose` 与字重令牌（`--fw-regular/medium/semibold/bold`）。所有字号引用令牌。
**适用场景**：全局文本。
**推荐复用**：**Ant Design 的 `fontSize` token（12/14/16/20/24/30/38）** + **Tailwind 的 type scale**；标题字体可保留 Chakra Petch（科技感），但需确保中文回退到 Noto Sans SC（已做）。
**落地改动**：在 `design-tokens.css` 定义阶梯；批量将散落 `font-size` 改为 `var(--fs-1)` 等（可用脚本半自动替换 + 人工核对）。

### G-2 中英文混排与行高优化
**目标效果**：正文行高统一 1.6（现 `1.4`/`1.5`/`1.7` 混用），数字/英文用等宽或 `font-variant-numeric: tabular-nums`（统计值对齐）。
**适用场景**：统计卡、表格、图表 tooltip。
**推荐复用**：Ant Design `lineHeight` token。
**落地改动**：`.ui-stat-value`/表格数字加 `font-variant-numeric: tabular-nums`；正文类统一 `line-height: var(--lh-normal)`。

### G-3 字体加载与降级
**现状**：`@import url('fonts/google-fonts.css')`（行内字体可能走本地 woff2，已下载 100+ 个 `font-*.woff2`）。需确认是否在线 CDN（离线部署风险）。
**目标效果**：若系统部署在**内网/离线**，Google Fonts 需自托管（项目已有 woff2，应已自托管）；在线环境保留 CDN 并加 `font-display: swap` 防 FOIT。
**适用场景**：首屏。
**推荐复用**：`font-display: swap` 标准实践。
**落地改动**：确认 `google-fonts.css` 指向本地 woff2；为 `@font-face` 补 `font-display: swap`。

## H. 页面布局的间距 / 对齐 / 响应式适配

### H-1 用间距令牌（Spacing Scale）统一留白
**现状**：`padding/margin/gap` 全是魔法数字（8/10/12/14/16/18/20px 混用），无间距系统；卡片 `padding:18px 20px`、按钮 `9px 18px` 各自写死。
**目标效果**：建立 `--space-1:4 / 2:8 / 3:12 / 4:16 / 5:20 / 6:24 / 8:32px` 令牌，统一卡片/按钮/栅格间距，确保「8px 基准网格」对齐。
**适用场景**：全局布局。
**推荐复用**：**Ant Design `padding`/`margin` token** + **8pt grid**（Material）。
**落地改动**：在 `design-tokens.css` 定义；逐步替换魔法数字（优先替换高频组件 `.ui-card/.ui-btn/.ui-modal`）。

### H-2 侧边面板与搜索栏的响应式重构
**现状**：布局存在「硬编码尺寸」——`--panel-width:360px`（styles.css:39）、搜索栏 `margin-left:300px`（styles.css:127，强依赖 logo 宽度）、`topbar` 固定 `120px` 高。窄屏下搜索栏被 `width:180px` 强行压缩，导航两行在手机上会拥挤。
**目标效果**：搜索栏改用 flex 自适应（不依赖 `margin-left:300px`）；侧边面板在 ≤768px 转为抽屉/全宽；导航在 ≤480px 允许横向滚动或折叠为汉堡菜单。
**适用场景**：平板/手机访问。
**推荐复用**：**Ant Design `Layout`（`Sider`/`Header` 响应式 `breakpoint`）** + **Element Plus 抽屉 `Drawer`**（移动端侧栏）。
**落地改动**：搜索栏父级用 `flex:1`；侧边面板 `@media(max-width:768px)` 改为 `position:fixed` 全宽抽屉 + 遮罩；导航加 `overflow-x:auto`。

### H-3 响应式断点与容器规范
**现状**：断点零散（`768/700/480px` 混用，且 700 与 768 规则有重叠），无统一断点变量；部分组件（如 `#result-table`、`legend-container`）各自写了媒体查询。
**目标效果**：统一断点令牌 `--bp-sm:480 / md:768 / lg:1024 / xl:1280px`，按「移动优先」重组媒体查询；复杂表格在窄屏改用横向滚动而非压缩字号。
**适用场景**：全部页面。
**推荐复用**：**Bootstrap 5 / Tailwind 断点**（sm/md/lg/xl）。
**落地改动**：在 `design-tokens.css` 定义断点；合并重复的 700/768 规则；表格窄屏加 `overflow-x:auto` 容器而非 `font-size:12px`。

### H-4 对齐与栅格
**目标效果**：统计卡/控件采用统一栅格（`grid` + `gap:var(--space-4)`），标签-控件对齐用一致基线（现部分表单 label 与 input 未垂直对齐）。
**适用场景**：表单、仪表盘。
**推荐复用**：**Ant Design `Row/Col` 24 栅格** 或 CSS Grid `repeat(auto-fit, minmax(...))`（已有 `ui-stat-grid` 雏形，复用并推广）。

## I. 优先级与落地路线图

| 优先级 | 项 | 工作量 | 收益 |
|---|---|---|---|
| 🔴 P0（必做·低成本高收益） | B-2 reduced-motion、C-3 焦点环、D-1 弹窗焦点陷阱/滚动锁、F-2 表单校验体系、C-1 按钮体系收敛、清理死代码（es-select/ui-input/ui-skeleton） | 中 | 可访问性 + 一致性 + 去重 |
| 🟠 P1（重要） | A-1/A-2/A-3 色彩令牌分层、G-1 字号阶梯、H-1 间距令牌、B-3 加载动画收敛、E-1 下拉键盘化、D-2 移动端弹窗 | 中-大 | 设计系统奠基，后续改一处生效 |
| 🟡 P2（增强） | B-5 骨架屏接入、B-6 错峰入场、H-2/H-3 响应式重构、G-3 字体 swap、D-3 富内容弹窗、F-1 聚焦态统一 | 大 | 观感与体验上台阶 |

**建议执行顺序**：先 P0 修「正确性/可访问性/去重」问题（不引入视觉变动风险），再用 `design-tokens.css` 一次性落地 A/G/H 的令牌（P1），最后做体验增强（P2）。所有令牌改动均「只改 `:root`/令牌文件即可全站生效」，符合「不重复造轮子、可复用成熟设计系统」的目标。
