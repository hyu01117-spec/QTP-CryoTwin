# 决策支持模块技术思路

> 所属系统：青藏高原冰冻圈灾害数字孪生系统
> 对应后端：`llm.py`（决策支持智能体）、`expert.py`（院士专家名录）、`decision.py`（防灾决策内容库）、`expert_kb.py`（真实数据知识库 / RAG 数据层）
> 对应前端：`decision.html`（决策支持页）
> 文档性质：模块级技术思路（定位、技术路线、核心方案、关键设计决策、接口关系）

---

## 1 模块定位与目标

决策支持模块是系统的**"人—机"智能交互中枢**，面向应急管理与防灾减灾决策人员，将上游"灾害数据库—过程模拟—风险评估"产出的**真实数据资产**，转化为可解释、可追溯、可执行的决策建议。其目标有三：

1. **智能问答**：以检索增强（RAG）的大语言模型智能体，回答冰冻圈灾害机理、风险评估解读、防灾措施建议等专业问题，并强制引用系统真实数据、标注来源，杜绝"虚构数据"。
2. **专家智库**：提供基于公开学术资料整理的院士/专家名录（单位、领域、成果、公开联系方式），支撑科研协作与专家咨询。
3. **决策内容库**：沉淀真实灾害案例与工程/非工程措施方法学，为业务人员提供可直接复用的防灾减灾知识。

模块严格遵循"**不编造数据、以物理过程为依据、安全第一**"的智能体行为准则，所有对外结论均可溯源至系统内部或公开权威数据。

## 2 总体技术路线

```
                        ┌──────────────── 真实数据知识库（RAG 数据层）────────────────┐
                        │  expert_kb.py → SQLite: expert_kb.db                        │
                        │  源：8类灾害GeoJSON / 气象站 / 县域GDP·人口 / 水库·水坝·电站    │
                        │      / 冰川·湖泊·河网·冻土 / ERA5索引 / 方法学文本            │
                        └───────────────────────────┬──────────────────────────────┘
                                                    │ build_context(question)
用户提问（decision.html）                            ▼
        │                                  解析灾害类型 / 区域 / 年份 → 检索 → 组装上下文 + 引用清单
        ▼                                            │
 /api/llm/chat（POST, SSE）◄─────────────────────────┘
        │  ① 组装 messages：系统提示词(可管理端配置) + 最近≤20条历史(单条≤4000字)
        │  ② 将真实数据注入末条用户消息（强制 [数据源:xxx] 标注）
        │  ③ 流式转发 DeepSeek（stream=True, temperature=0.7）
        ▼
  前端流式渲染（思维链 + 引用标注）
        │
        ├── 专家名录：GET /api/expert/profiles (?field=?q)  /  /api/expert/fields
        └── 决策内容：GET /api/decision/content（防灾实例 / 工程措施 / 非工程措施）
```

## 3 核心技术方案

### 3.1 决策支持智能体（llm.py）

**角色与边界**。智能体以 `SYSTEM_PROMPT` 固化"自然与人文地理学家兼冰冻圈科学家"角色，明确 12 项能力维与 12 条行为准则（不编造数据、以物理过程为依据、气候系统观、避免地理决定论、尺度敏感、气候变化背景、安全第一等），并将能力边界限定在地理学与冰冻圈防灾减灾领域，超界问题礼貌拒答。系统提示词可由管理端在 `admin.db` 的 `settings.agent_system_prompt` 动态覆写，未配置时回退内置默认。

**对话代理（/api/llm/chat）**。后端作为 DeepSeek（OpenAI 兼容协议）的**安全代理**，密钥仅存于后端 `config`（绝不暴露前端）：
- `build_messages()` 组装消息：注入系统提示词，并对历史做**双重限流**——仅保留最近 `MAX_HISTORY_MESSAGES=20` 条、单条内容截断至 `MAX_MESSAGE_CHARS=4000`，防止长会话刷接口/刷费用。
- **检索增强（RAG）**：调用 `expert_kb.build_context(question)` 解析问题中的灾害类型、区域、年份，检索系统真实数据，组装为结构化上下文；注入到末条用户消息前，并要求"回答必须引用并在引用处标注 `[数据源：xxx]`；数据未覆盖的内容明确说明'系统数据未覆盖'"。检索异常时**降级为纯对话**（记 warning，不阻断服务）。
- **流式转发**：以 `requests` + `stream=True` 拉取 DeepSeek SSE，逐条透传为前端 `text/event-stream`（`data: {content}`），遇 `[DONE]` 收尾；上游非 200 或异常时透传错误详情，便于定位。

**健康检查（/api/llm/health）**：仅返回模型名与"是否已配置密钥"布尔，不泄露密钥。

### 3.2 真实数据知识库（expert_kb.py，RAG 数据层）

**构建（幂等）**。`build_kb(force=False)` 将分散的真实数据资产统一入库至 `data/processed/db/expert_kb.db`（SQLite），包含 8 张表：`kb_disaster_cases`（8 类灾害事件，字段随灾害类型适配：成因、死亡/转移人数、影响面积、过程降雨、海拔、堵江时长、冰川跃动参数等）、`kb_stations`（气象站）、`kb_counties`（县域人口/GDP，含 `has_economy` 标记）、`kb_infra`（水库/水坝/电站）、`kb_geo_overview`（冰川/湖泊/河网/冻土/居民地/道路/铁路要素计数）、`kb_era5_stats`（ERA5 与各索引库现状）、`kb_methods`（风险评估方法学文本）、`kb_sources`（数据源清单与构建时间）。已存在且非 `force` 时跳过，保证可重复执行、不破坏既有数据。

**检索（build_context）**。问题解析采用轻量**关键词路由**而非向量库：
- `_detect_type()`：基于各灾害类型关键词表（如融雪→`『融雪','雪融','SFs'…`」）+ 通用词（"洪水"→`rainfall_floods`）识别灾害类型；
- `_detect_region()` / `_detect_year()`：匹配高原行政区/地名表与四位年份；
- `search_cases()`：按类型/区域/年份/关键词构造参数化 SQL，分级回退（类型→区域→全量）保证有结果；
- `get_exposure()`：区域匹配县域暴露度，无区域时回退人口/GDP 前列总览；
- 最终组装为"真实灾害事件案例 / 区域承灾体暴露度 / 地理要素概览 / 气象数据现状 / 方法学"五段式上下文，并产出 `citations` 引用清单，供前端溯源。

### 3.3 院士专家名录（expert.py）

**定位**：参照行业专家库管理办法的**专家名录库**（非个人画像）。数据源 `data/webgis/content/expert_profiles.json`（公开学术资料整理，含 `sources` 来源 URL）。

**接口**：
- `GET /api/expert/profiles`：返回精简字段（姓名/头衔/单位/领域/简介/成果/论文/单位公开联系方式），支持 `?field=领域` 筛选与 `?q=关键词` 跨字段（姓名/领域/单位/简介）搜索；按 `sort` 排序。
- `GET /api/expert/fields`：以领域字段首个顿号/逗号前的主分类聚合，供前端筛选器。

**科研规范**：仅展示单位公开联系方式（单位/地址/公开电话/官网），不展示个人私密信息并提示"请通过单位联系"；前端显著声明"档案为公开资料整理，供科研参考"。

### 3.4 决策内容库（decision.py）

数据源 `data/webgis/content/decision_content.json`，每条记录携带 `source`（权威来源）。`GET /api/decision/content` 一次性返回三类内容及其计数：
- **防灾实例**：青藏高原及同类冰冻圈灾害真实案例（成因机制/过程影响/处置经验/启示）；
- **工程措施**：防洪、泥石流防治、滑坡与堰塞湖、冰湖防治、冻土工程、雪害防治六类；
- **非工程措施**：监测预警、应急预案、群测群防、宣传教育、风险管理、保险与救助六类。
内容基于政府通报、权威媒体、学术文献、单位官网整理，机制描述真实可靠。

## 4 关键设计决策

1. **后端代理 + 密钥不出后端**：LLM 调用经 Flask 后端统一转发，API Key 仅驻留服务端配置，前端只持 `/api/llm/chat`，从架构上杜绝密钥泄露。
2. **RAG 强制溯源、禁编造**：真实数据以"【系统真实数据…】"块注入并强制 `[数据源:xxx]` 标注；数据未覆盖须显式声明，使智能体结论可审计、可追责，契合科研规范。
3. **关键词路由而非向量库**：知识库规模适中、字段结构化强，采用类型/区域/年份关键词 + 参数化 SQL 检索，成本低、可解释、可回退；降级链（类型→区域→全量）保证总有上下文。
4. **历史与长度双重限流**：`MAX_HISTORY_MESSAGES=20` 与 `MAX_MESSAGE_CHARS=4000` 兼顾多轮连贯与费用/接口安全。
5. **系统提示词可管理端配置**：`agent_system_prompt` 存于 `settings` 表，支持业务人员在不改代码情况下微调智能体角色，且 `is_default` 标记区分默认/自定义。
6. **专家名录"去个人化"**：仅公开单位渠道、附 `sources`，在"可利用专家资源"与"隐私合规"间取得平衡。
7. **知识库构建幂等**：`build_kb` 可重复运行，存在则跳，便于数据更新后重建且不破坏运行态。

## 5 模块间接口关系

**上游依赖（输入）**
- **灾害数据库**（`disaster.py` / `data/raw/geo/*.geojson`）：`kb_disaster_cases` 直接由 8 类灾害事件 GeoJSON 构建，是 RAG 检索的核心语料；`/api/expert` 与 `/api/decision/content` 亦依赖该真实数据底座。
- **灾害过程模拟**（`simulate.py`）：ERA5/径流/淹没栅格经 SQLite 索引被 `kb_era5_stats` 收录，支撑智能体对"某日径流/淹没"问题的真实应答；智能体引导用户"先在系统中完成模拟/识别再咨询"，与模拟模块形成闭环。
- **风险评估**（`alert.py`）：方法学文本（`R=H×E×V`、五级分级、阈值场、流域约束）写入 `kb_methods`，智能体据此解读风险分级；风险"高风险区识别"结论与内容库（工程/非工程措施）联动。
- **社会经济数据**（`economy.py` / `preprocess_economy.py`）：县域 GDP/人口落入 `kb_counties`，作为 RAG 暴露度检索源。

**下游服务（输出）**
- **首页 / 各业务页**：`decision.html` 为统一入口，聚合智能体对话、专家名录、决策内容三块；对话结论可回链至数据库/模拟/评估页面。
- **系统管理**（`admin.py`）：`/api/admin/agent-config` 读写智能体系统提示词（依赖本模块 `SYSTEM_PROMPT` 默认值）；决策接口产生的访问不直接写 `admin_logs`（日志由管理模块统一采集关键操作）。

## 6 输入/输出与数据约定

- **输入**：用户自然语言问题（含可选多轮 `messages`）；专家检索参数 `field/q`；决策内容库为静态 JSON。
- **输出**：`/chat` 返回 SSE 流（`data: {"content": "…"}` 直至 `data: [DONE]`），错误以 `data: {"error": "…"}` 透传；`/profiles`、`/fields`、`/content` 返回结构化 JSON（含 `count`）。
- **数据约定**：知识库统一以 `data/processed/db/expert_kb.db` 为单一检索源；所有引用带 `source_file` / `reference` 字段；坐标统一经 `_geom_centroid()` 取质心；金额单位与县域统计保持一致（GDP 万元）。

---

## 7 已知边界与后续规划

- **RAG 为关键词路由**：未引入向量检索/语义召回，长难句或跨类型问题的召回精度有限；后续可接入 embedding 向量库做语义检索，并支持多跳推理。
- **知识库需手动重建**：`expert_kb.db` 随数据更新需重跑 `build_kb(force=True)`；规划由系统管理模块提供"一键重建知识库"入口并展示构建状态。
- **智能体未接实时计算结果**：当前对话以"已落库数据"为检索对象，未直接调用在线模拟/评估接口；后续可将风险评估结果作为实时上下文注入，实现"问即算"。
- **专家名录与内容库为静态整理**：依赖人工维护 JSON；规划支持管理端可视化编辑与审核流程，强化来源合规。
- **模型依赖外部 API**：DeepSeek 不可用时智能体不可用（仅降级为无数据对话）；规划增加备用模型与离线规则库兜底。
