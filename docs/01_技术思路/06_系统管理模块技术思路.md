# 系统管理模块技术思路

> 所属系统：青藏高原冰冻圈灾害数字孪生系统
> 对应后端：`auth.py`（认证与会话）、`system.py`（运行状态）、`admin.py`（用户/角色/权限/日志/数据/智能体配置）、`admin_db.py`（管理数据库）
> 对应前端：`login.html`（登录）、`admin.html`（系统管理页）
> 文档性质：模块级技术思路（定位、技术路线、核心方案、关键设计决策、接口关系）

---

## 1 模块定位与目标

系统管理模块是平台的**安全基座与运维中枢**，承担三项核心职责：

1. **身份认证与会话管理**：基于 Flask 会话（Cookie + `SECRET_KEY`）实现登录/登出/当前用户识别，并以 `login_required` 装饰器为全站受保护接口提供统一登录校验。
2. **基于角色的访问控制（RBAC）**：以"用户—角色—权限点"三级模型实现细粒度授权，`permission_required` 装饰器在写操作前做权限点校验，保障各业务功能按职责可用。
3. **运维可观测与配置**：实时系统状态（版本、运行时长、数据资产计数、活跃用户、存储占用）、操作审计日志、数据目录浏览与受控上传/删除、以及决策智能体系统提示词的可视化配置。

模块目标是在不改动业务代码的前提下，使系统具备可审计、可授权、可运维的生产级管理能力。

## 2 总体技术路线

```
                 ┌──────────── 管理数据库 admin.db (SQLite) ────────────┐
                 │ users │ roles │ permissions │ role_permissions       │
                 │ admin_logs（操作审计）│ settings（key-value）        │
                 └───────────────────────┬─────────────────────────────┘
                                         │ 读写（admin_db.py 封装）
       登录 ──► /api/auth/login          ▼
  session{user,role_id,role_code}  ┌──────────── 认证/权限装饰器 ────────────┐
        │                           │  login_required：未登录→401           │
        ▼                           │  permission_required(code)：缺权→403  │
  /api/auth/me（前端知角色）         └───────────────┬───────────────────────┘
                                    写操作经装饰器校验后进入 admin.py 各路由：
   ┌──────────────┬──────────────┬──────────────┬────────────────┬──────────────┐
   │ 用户管理      │ 角色/权限管理 │ 系统日志     │ 数据管理        │ 智能体配置   │
   │ users CRUD   │ roles/perms  │ logs 查询/统计│ data-tree/files │ agent-config │
   │ 密码重置/批量 │ 权限指派     │ 清空         │ 上传/删除(防穿越)│ (→llm.py)   │
   └──────────────┴──────────────┴──────────────┴────────────────┴──────────────┘
   /api/system/status ──► 实时状态（公开，不含敏感信息）
```

## 3 核心技术方案

### 3.1 认证与会话（auth.py）

- **登录（`/api/auth/login`）**：校验用户名→`check_password_hash` 比对（密码以 `werkzeug` 哈希存储，非明文）；校验 `status==1`（禁用账号返回 403）；通过后 `session.clear()` 重建会话并写入 `user / user_id / role_id / role_code / display_name`，置 `session.permanent=True`；同时 `touch_last_login` 更新最后登录时间、`add_log` 记登录审计。
- **登出（`/api/auth/logout`）**：先记退出日志再 `session.clear()`。
- **当前用户（`/api/auth/me`）**：回传 `user / display_name / role_code`，供前端路由守卫与界面角色判定。
- **`login_required` 装饰器**：包裹受保护视图，缺 `session.user` 返回 `401`，前端据此跳转 `login.html`。

### 3.2 基于角色的访问控制（admin.py + admin_db.py）

**数据模型（admin_db.py）**。`admin.db` 含六表：`users`（用户名唯一、密码哈希、角色外键、状态、创建/最后登录时间）、`roles`、`permissions`、`role_permissions`（角色—权限多对多）、`admin_logs`、`settings`。

**权限点（14 项）**分组定义：`user:view/create/update/delete`、`role:view/create/update/delete`、`permission:view/assign`、`log:view`、`setting:edit`、`system:view`、`data:manage`。

**内置角色**：`admin`（全权限）、`operator`（日常运维+数据管理，不含 `user:delete`/`role:delete`）、`viewer`（只读）。

**`permission_required(code)` 装饰器**：从 `session.user_id` 经 `get_user_permission_codes` 取当前角色权限码集合，缺码返回 `403`。与 `login_required` 组合，形成"先登录、再鉴权"的双层防线，覆盖 admin 全部写接口。

**用户/角色/权限运维**：用户支持分页+关键词检索、新增（密码≥6 位）、编辑、删除、密码重置、批量删除/批量启停；角色支持 CRUD 与权限指派（`set_role_permissions` 先删后插）；权限列表只读下发。

### 3.3 系统状态（system.py）

`GET /api/system/status` 为**公开**接口（不含敏感信息），实时探测：`python/flask/torch` 版本、平台、`uptime`（自进程启动计时）、`db_exists`、各资产目录 `.tif` 计数（模型/阈值/径流/淹没）、**近 24 小时活跃用户数**（查 `admin_logs` `datetime('now','-1 day')` 去重）、**存储占用**（`_dir_size_mb` 递归 `STATIC_BACKEND_DIR`，带 60s 缓存避免每次遍历 12GB 目录）、`server_time`。该接口替代前端随机 mock，使状态真实可观测。

### 3.4 操作审计日志（admin_db.add_log / admin.py）

关键操作（登录、退出、增删改用户/角色、权限配置、上传/删除数据、修改密码、清日志、智能体配置）统一经 `add_log(username, action, detail, ip)` 写入 `admin_logs`；日志写入采用 `try/except pass` **非阻塞**设计，失败不影响主流程。`/api/admin/logs` 支持按用户/动作/关键词查询与统计（近 N 天每日量、动作分布、用户排行），并支持清空。

### 3.5 数据管理（admin.py，受控文件操作）

`/api/admin/data-tree`（目录树含递归文件数/大小）、`/api/admin/data-files`（分页列文件，目录空时自动建）、`/api/admin/data-files/upload`（上传）、`/api/admin/data-files`（DELETE 删文件/子目录）。覆盖真实 `data/` 与 `uploads/` 两棵树。**安全防护**：
- `_resolve_data_dir`：将相对路径解析到 `data/` 或 `uploads/` 内部，用 `os.path.realpath` + `os.path.commonpath` 校验防止**路径穿越**（`..`、`\` 等越界返回 `None`）；
- `_resolve_data_file` + `secure_filename`：文件名白名单，禁止含 `..`、`/`、`\`；
- 上传重名自动加后缀，删除经权限点 `data:manage` 校验。

### 3.6 智能体配置桥接（admin.py → llm.py）

`/api/admin/agent-config`（GET/PUT/DELETE）读写 `settings.agent_system_prompt`：GET 返回当前提示词并标 `is_default`（无配置时回退 `llm.SYSTEM_PROMPT`）；PUT 校验非空后存库；DELETE 恢复默认。使决策支持模块的智能体角色可在管理端可视化微调，无需改代码。

### 3.7 种子数据与增量升级（admin_db.init_admin_db）

首次启动幂等建表并写入种子：权限点、内置三角色及其授权、默认管理员账号（来自 `.env`，缺省 `admin/admin123`）。**老库升级兼容**：每次初始化扫描 `PERMISSIONS` 增量补种新权限点，并自动授予 `admin`/`operator`，保证升级不丢权、不覆盖既有密码。

## 4 关键设计决策

1. **RBAC 而非硬编码**：以"权限点"解耦功能与角色，新增功能只需注册权限点并指派给角色，业务代码零改动即可纳管。
2. **双层装饰器防线**：`login_required` + `permission_required` 组合，所有 admin 写接口强制鉴权；401/403 语义清晰，前端据此分流。
3. **会话态而非 JWT**：采用 Flask 原生 session（服务端 `SECRET_KEY` 签名），实现简单、无需额外令牌基础设施；`session.permanent` 保证跨请求持久。
4. **密码哈希存储**：`werkzeug` 的 `generate/check_password_hash`，库内无明文；重置/修改密码均重新哈希。
5. **安全护栏（防误操作/越权）**：禁止删除/禁用自身；删除管理员前校验"至少保留 1 个启用 admin"；`admin` 角色不可删；角色下仍有用户时不可删角色——从数据层杜绝锁死系统。
6. **路径穿越防护**：数据管理全部路径经 `realpath + commonpath` 边界校验，杜绝 `../` 逃逸至系统目录。
7. **状态接口轻量与缓存**：存储占用 60s 缓存，避免高频遍历大目录；状态接口公开但不含密钥/用户明细。
8. **日志非阻塞**：`add_log` 异常静默，确保审计不影响业务可用性。
9. **种子幂等 + 增量补种**：`init_admin_db` 可重复执行，升级自动补权限，兼顾初始化与版本演进。

## 5 模块间接口关系

**横向基座（被依赖）**
- **全站受保护接口**：`auth.login_required` 与 `admin.permission_required` 是 admin 各路由及（经扩展）任意业务写操作的安全基座；`/api/auth/me` 供前端全局路由守卫。
- **决策支持**（`llm.py`）：`/api/admin/agent-config` 直接读写 `settings.agent_system_prompt`，是智能体系统提示词的唯一管理入口。
- **数据管理 ↔ 各数据模块**：`data/` 与 `uploads/` 的文件浏览/上传/删除，面向灾害数据库、过程模拟、风险评估等所有以 `data/` 为数据根的模块，提供受控的数据运维通道。
- **系统状态 ↔ 各资产目录**：`system.status` 实时统计模型/阈值/径流/淹没栅格与存储占用，依赖全局 `config`（`STATIC_BACKEND_DIR`、`MODELS_DIR`、`THRESHOLDS_DIR`、`RUNOFF_OUTPUT_DIR`）。

**前端入口**
- `login.html`：调用 `/api/auth/login`、`/me`；
- `admin.html`：聚合用户/角色/权限/日志/状态/数据/智能体配置六类管理视图，分别对接 `admin.py` 与 `system.py` 接口。

## 6 输入/输出与数据约定

- **输入**：登录凭据（username/password）；用户/角色/权限的 JSON 表单；日志查询参数（days/user/action/keyword/limit）；数据操作相对路径与文件名；智能体提示词文本。
- **输出**：登录返回 `user/display_name/role_code`；各管理接口统一 `{success, message, data}` 信封；`system.status` 返回状态 JSON；日志/用户/角色分页结构含 `total/total_pages`。
- **数据约定**：管理库统一位于 `data/processed/db/admin.db`；密码仅存哈希；审计日志 `created_at` 取服务端时间；设置项以 `key` 唯一（`ON CONFLICT` upsert）。

## 7 已知边界与后续规划

- **会话态无集中失效**：基于 Cookie session，缺乏服务端会话黑名单，改密/禁用后需等会话自然过期；规划引入服务端会话表或短期令牌以支持即时吊销。
- **权限点为静态枚举**：新功能权限需改代码注册；可演进为管理端可视化注册权限点。
- **数据管理仅文件级**：当前支持浏览/上传/删除，未做版本管理与回收站；规划增加软删除与操作二次确认。
- **单管理员种子弱口令**：默认 `admin/admin123` 仅适用于初始化，生产须强制改密并启用 HTTPS。
- **日志无归档**：`admin_logs` 清空即永久丢失；规划按周期归档至独立存储，支撑长期审计。
- **角色互斥未建模**：尚未支持"一人多角色"或角色继承；如业务需要，可在 `users.role_id` 扩展为多对多。
