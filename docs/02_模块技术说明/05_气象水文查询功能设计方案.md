> 文档基线：2026-09-07，对应 commit `4c47801`
> 适用对象：接手"气象水文 → 温度/降水"图层后续查询功能的开发者
> 阅读顺序：第 1 章确认对应关系 → 第 2 章选型依据 → 第 3 章前端 → 第 4 章后端 → 第 5 章落地步骤

## 0. 一句话方案

**复用现有 `/api/query/variables`、`/api/query/list` 接口和 `loadGeoTiffLayer` 渲染函数**，在前端把"气象水文"模块下"温度数据 / 降水数据"两个空壳 checkbox 升级为"按变量 + 起止日期 → 列出日栅格 → 选中后上图"。后端补一个"轻量日期范围目录扫描"接口即可，其它全部走现成代码。

> ⚠️ **实现后重要更正（见 §5.5）**：TIF 数据实测已是**摄氏度/毫米**，不是 ERA5 原生 K/m，
> 故正文 §1.1 / §3.2 / §4.3 里"需做 K→℃、m→mm 换算"的设想**已作废**，无需任何换算。
> 温度可含负值、0 为合法冰点，渲染透明规则须按变量区分（详见 §5.5 第 3/4 条）。

## 3. 前端方案

### 3.1 查询交互方式（用户视角）

```
┌─ 气象水文 ──────────────────────────────────┐
│ ☐ 温度数据   ← 勾选                        │
│   ├ 子选项: ○ 日均温  ○ 日最高温           │
│   ├ 起: [ 2024-06-01 ]  止: [ 2024-07-01 ]│
│   ├ [ 查询 ]                                │
│   └ 结果表: 日期 / 数值(mm) / [加载到地图]  │
│ ☐ 降水数据   ← 勾选                        │
│   ├ 子选项: ○ 日总降水  ○ 日最大降水       │
│   ├ 起 / 止 / [查询] / 结果表              │
└─────────────────────────────────────────────┘
```

交互细节：
1. **勾选 "温度数据"**：展开该分类下的二级面板（变量单选 + 日期范围 + 查询按钮 + 结果区）。
2. **查询按钮**：调 `GET /api/query/list?variable=X&start_date=…&end_date=…&calculate_mean=true`，返回 `{data:[{date, mean_value, unit, file_url}]}`，渲染成紧凑表格。
3. **结果表行**：每行有"加载到地图"按钮，调 `window.loadGeoTiffLayer(file_url, variable, date)`（栅格直接上图，叠加在底图上）。
4. **取消勾选**：移除已加载的 TIF 图层 + 关闭已弹出的图例。
5. **重复勾选**：保留旧图层（避免每次都重新 fetch + 解码 TIF），仅切换可见性。

### 3.3 新增 JS 模块：`webgis_frontend/js/meteo-query.js`

> 这是核心新文件。把栅格渲染从 `simulate.js` 抽出（或者复制 `loadGeoTiffLayer` 内的 canvasFunction 段），让不加载 simulate.js 的页面也能用。

```js
// meteo-query.js —— 气象水文模块：温度/降水日栅格查询与上图
// 依赖：window.UI、window.map、window.ol、window.GeoTIFF、window.showLoading
//       window.loadGeoTiffLayer（来自 simulate.js / geotiff-render.js）

(function () {
  'use strict';

  // 与 config.VARIABLES 同步；单位与 simulate.js i18n.units 保持一致
  const VAR_META = {
    temperature_2m:           { label: '日均温',    unit: '℃', rawUnit: 'K',     offset: -273.15, scale: 1,     dir: 'temperature' },
    temperature_2m_max:       { label: '日最高温',  unit: '℃', rawUnit: 'K',     offset: -273.15, scale: 1,     dir: 'temperature' },
    total_precipitation_sum:  { label: '日总降水',  unit: 'mm', rawUnit: 'm',    offset: 0,       scale: 1000,  dir: 'precipitation' },
    total_precipitation_max:  { label: '日最大降水',unit: 'mm', rawUnit: 'm',    offset: 0,       scale: 1000,  dir: 'precipitation' },
  };

  // 各变量已加载的图层（key = variable|date），避免重复解码
  const loadedLayers = {};   // { 'temperature_2m|2024-06-01': olLayer }
  const activeControl = { temperature: null, precipitation: null };

  // 入口：checkbox change → 展开 / 收起子面板 + 触发默认查询
  function initMeteoQuery() {
    bindCheckbox('layer-temperature', 'temperature');
    bindCheckbox('layer-precipitation', 'precipitation');
    bindQueryButton('meteo-temp-query', 'temperature');
    bindQueryButton('meteo-precip-query', 'precipitation');
  }

  function bindCheckbox(checkboxId, dir) {
    const cb = document.getElementById(checkboxId);
    const panel = document.getElementById(`meteo-${dir}-subpanel`);
    if (!cb || !panel) return;
    cb.addEventListener('change', () => {
      panel.hidden = !cb.checked;
      if (!cb.checked) removeDirLayers(dir);   // 关闭分类时一并移除
    });
  }

  function bindQueryButton(btnId, dir) {
    const btn = document.getElementById(btnId);
    if (!btn) return;
    btn.addEventListener('click', () => runQuery(dir));
  }

  async function runQuery(dir) {
    const varKey = getSelectedVariable(dir);
    const start  = document.getElementById(`meteo-${dir}-start`).value;
    const end    = document.getElementById(`meteo-${dir}-end`).value;
    if (!varKey || !start || !end) {
      UI.toast('请选择变量并填写日期范围', 'warning'); return;
    }
    if (start > end) { UI.toast('开始日期不能晚于结束日期', 'warning'); return; }

    showLoading(true, '查询中…');
    try {
      const url = `/api/query/list?variable=${encodeURIComponent(varKey)}` +
                  `&start_date=${start}&end_date=${end}&calculate_mean=true`;
      const res = await fetch(url);
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const json = await res.json();
      if (json.status !== 'success') throw new Error(json.message || '查询失败');
      renderResult(dir, varKey, json.data || []);
    } catch (e) {
      console.error('[meteo-query] 查询失败:', e);
      UI.toast(`查询失败：${e.message}`, 'error');
    } finally {
      showLoading(false);
    }
  }

  function getSelectedVariable(dir) {
    const sel = document.querySelector(`input[name="meteo-${dir}-var"]:checked`);
    return sel ? sel.value : null;
  }

  function renderResult(dir, varKey, rows) {
    const tbody = document.querySelector(`#meteo-${dir}-table tbody`);
    tbody.innerHTML = '';
    const meta = VAR_META[varKey];
    rows.forEach(row => {
      const tr = document.createElement('tr');
      const meanDisplay = row.mean_value == null
        ? '—'
        : (meta.offset || meta.scale !== 1)
            ? (row.mean_value * meta.scale + meta.offset).toFixed(2)
            : row.mean_value.toFixed(2);
      tr.innerHTML = `
        <td>${row.date}</td>
        <td>${meanDisplay} ${meta.unit}</td>
        <td><button class="ui-btn ui-btn-sm" data-act="load"
                     data-var="${varKey}" data-date="${row.date}"
                     data-url="${row.file_path}">加载</button></td>`;
      tbody.appendChild(tr);
    });
    tbody.querySelectorAll('button[data-act=load]').forEach(b => {
      b.addEventListener('click', () => loadToMap(b.dataset.var, b.dataset.date, b.dataset.url, b));
    });
    UI.toast(`查询到 ${rows.length} 条数据`, rows.length ? 'success' : 'warning');
  }

  async function loadToMap(varKey, date, relPath, btn) {
    const fileUrl = relPath.startsWith('/') ? relPath : `/tif/${relPath}`;
    if (loadedLayers[`${varKey}|${date}`]) {
      loadedLayers[`${varKey}|${date}`].setVisible(true);
      btn.textContent = '已上图'; btn.disabled = true;
      return;
    }
    if (typeof window.loadGeoTiffLayer !== 'function') {
      UI.toast('栅格渲染模块未加载，请联系管理员', 'error'); return;
    }
    showLoading(true, '加载栅格…');
    try {
      const layer = await window.loadGeoTiffLayer(fileUrl, varKey, date);
      loadedLayers[`${varKey}|${date}`] = layer;
      btn.textContent = '已上图'; btn.disabled = true;
    } catch (e) {
      console.error('[meteo-query] 加载栅格失败:', e);
      UI.toast(`加载失败：${e.message}`, 'error');
    } finally {
      showLoading(false);
    }
  }

  function removeDirLayers(dir) {
    Object.keys(loadedLayers).forEach(k => {
      const [v] = k.split('|');
      if (VAR_META[v] && VAR_META[v].dir === dir) {
        window.map.removeLayer(loadedLayers[k]); delete loadedLayers[k];
      }
    });
    if (activeControl[dir]) { window.map.removeControl(activeControl[dir]); activeControl[dir] = null; }
    // 复位"加载"按钮
    document.querySelectorAll(`#meteo-${dir}-table button[data-act=load]`)
      .forEach(b => { b.textContent = '加载'; btn.disabled = false; });
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initMeteoQuery);
  } else {
    initMeteoQuery();
  }
})();
```

> 备注：上例**复用** `window.loadGeoTiffLayer`（来自 simulate.js）—— 因此**还需要**从 simulate.js 把它和依赖的 `interpolateColor` / `createLegend` 抽到独立的 `js/geotiff-render.js`，index.html / query.html 单独加载这个文件即可，不必拖入整个 simulate.js。具体抽离步骤见 §5.2。

`calculate_mean=true` 会用 `rasterio` 计算每个像元均值（`data_query.py:121-147`），单张 575 个文件 × 4322×1562 像元会很慢——**后端不要默认开 `calculate_mean=true`，由前端按钮触发**（默认 false；前端"加载到地图"按钮按需单独算）。

### 4.2 新增接口：`/api/query/range`

**目的**：避免前端一次性列出整年 575 个文件名（信息密度低、传输浪费），让前端能先拿到"该变量在指定日期范围内有数据的天数"和"最小/最大日期"，UI 上做日期边界提示和预校验。

```python
# 追加在 modules/data_query.py（紧跟 /api/query/list 之后）
@query_bp.route('/api/query/range', methods=['GET'])
def query_date_range():
    """返回某变量在索引库里的可用日期范围与数量。"""
    variable = request.args.get('variable')
    if not variable:
        return jsonify({'status': 'error', 'message': '缺少参数 variable'}), 400
    try:
        db_path = get_db_path()
        conn = sqlite3.connect(db_path)
        try:
            conn.row_factory = sqlite3.Row
            row = conn.execute(
                "SELECT MIN(date) AS min_date, MAX(date) AS max_date, COUNT(*) AS cnt "
                "FROM TibetanPlateau_index WHERE variable = ?", (variable,)
            ).fetchone()
        finally:
            conn.close()
        if not row or row['cnt'] == 0:
            return jsonify({'status': 'success', 'available': False})
        return jsonify({
            'status': 'success',
            'available': True,
            'variable': variable,
            'min_date': row['min_date'],
            'max_date': row['max_date'],
            'count':    row['cnt'],
        })
    except Exception as e:
        logger.exception('❌ /api/query/range 出错')
        return jsonify({'status': 'error', 'message': str(e)}), 500
```

**前端使用**：进入子面板时调一次，把 `<input type="date">` 的 `min`/`max` 设上，给用户一个明确的日期范围提示（避免出现"2024-01-01 ~ 2025-12-31 但库只有 2024 年"这种空查询）。

### 4.3 数据口径与单位契约（重要，必须和需求方确认）

| 字段 | 当前口径 | 建议契约（写入本节文档） |
|---|---|---|
| `temperature_*` 索引文件原始值 | K（ERA5 原生） | 返回给前端前**统一转为 ℃**（K - 273.15），单位 `unit = "℃"`；这样前端不需要知道原始单位 |
| `precipitation_*` 索引文件原始值 | m（ERA5 原生） | 返回给前端前**统一转为 mm**（×1000），单位 `unit = "mm"`；同上 |
| `mean_value` | 当前 `data_query.py:144` 直接返回原始单位 | 按上面契约换算 |
| 单位字段 | 当前没有 | 在 `/api/query/list` 的每条 `data` 中**新增 `unit` 字段**，值固定 `"℃"` 或 `"mm"` |
| 栅格 TIF 文件本身 | 保持原值不动 | 上图时调 `window.loadGeoTiffLayer` 会做分位拉伸 + 配色，**栅格图上不需要单位换算**（数值映射到 0~1 颜色区间，不需要语义单位） |

**实施要点**：
- 把单位换算集中放在 `data_query.py` 一个函数里（如 `_convert_to_display_unit(value, variable) -> Tuple[float, str]`），避免散落。
- `data` 中每条加 `unit` 字段；前端 VAR_META 中 `rawUnit/offset/scale` 在本方案**前端不参与计算**，只作展示（**实际换算走后端**，前端只展示）。
- ⚠️ 这是**对外口径变更**：与现行代码不一致，必须先和需求方确认。决策前保留兼容：在 `data_query.py` 用环境变量开关 `ERA5_UNIT_DISPLAY` 控制，未启用时返回原始值 + 注明单位；启用时按上面契约换算。

### 4.4 索引库访问模式（沿用，不改）

- `TibetanPlateau_index.db` 表 `TibetanPlateau_index`：`id, variable, date, file_path, bbox_minx, bbox_miny, bbox_maxx, bbox_maxy, bands, crs, created_at`（共 1460 行，见 §4 文档 1.3 节）

实现过程中基于代码实测做了三处偏离方案（均为降低回归风险）：

1. **simulate.html 未启用本功能、simulate.js 未改薄壳。**
   深入代码发现 `simulate.js` 是 3400 行单 `DOMContentLoaded` 闭包，渲染函数与其
   闭包变量（`loadingOverlay` / `i18n` / `tifLayer` / 图例）深度耦合，内部 12+ 处调用
   `loadGeoTiffLayer`。物理抽离会让 simulate.html 面临无法本地自动验证的回归。
   → 改为新建**自包含** `js/geotiff-render.js`（`window.renderGeoTiffLayer` / `removeGeoTiffLayer`），
   只给 index.html / query.html 使用；simulate.js 保持原样。代价是渲染逻辑有两份，bug 修复需同步。

2. **UI 按钮 / 表格不再复用 `ui-btn` / `ui-table`。**
   `query.html` 未引入 `components.css`（只有 index/simulate/alert 引了），用 `ui-btn`
   会让 query.html 的按钮无样式。→ 改为自包含 `.meteo-btn` / `.meteo-result-table`
   （追加在 `css/styles.css` 末尾），三处统一，无 components.css 依赖。

3. **单位无需换算 —— TIF 实测已是摄氏度 / 毫米。**
   用 rasterio 实测确认 `data/raw/TibetanPlateau/` 下 TIF **不是** ERA5 原生 K/m：
   温度 2024-01 为 **-30.7~14.2 ℃**（含负值），6 月 -17.3~27.0 ℃；降水 sum 0.001~72.6 **mm**、
   max 0~9.1 mm。`/api/query/list` 的 `mean_value` 即 ℃/mm（6/1 温度 3.09℃ 与 rasterio 直算一致），
   前端/后端均无需换算。此前"K/m 待换算"判断作废。

4. **图例布局统一对齐 simulate.js；色带按变量分派——温度反转彩虹、降水原版（最终决定）。**
   - **色带**：温度变量（temperature_2m / _max）= 把 simulate 那套 20 段彩虹**反转**
     （`colorStopsFor()` 内 `RAINBOW_STOPS.slice().reverse()` 并重排 value 递增），
     即**低温=蓝端、高温=红端**（用户拍板"低温蓝高温红"）；降水及其它变量用 simulate
     原版彩虹 `RAINBOW_STOPS`（小值红 → 大值深蓝，simulate.js:871-892）。
     颜色源统一，不另造色带常量（此前 TEMP_STOPS 冷暖数组已删除）。
   - **图例布局**：`createLegendControl` 对齐 simulate `createLegend`（simulate.js:548-694）：
     容器 140px / 标题中文名+单位（`label/unit`）/ **16 档等分** [min,max] / 顶档 `大于 max` /
     底档 `小于 min` / 色块取**每档中点**对应色带色 / 色块 28×14、行距 6px。
     温度与降水共用同一布局函数，仅传入色带不同。
   - **标签格式（用户给的实例，自上而下左闭右开）**：
     ```
     ≥15.7           顶档
     14.0～15.7      中间档（全角 ～；温度含负值，不能用 "-" 连接；档内不加 ＜）
     …
     ＜-8.7           底档
     ```
     小数位：**温度与降水均 1 位小数**（档位边界舍入后若重合会出现 "5.0～5.0"，
     则逐级增加小数位直到不重合，最多 3 位；降水整数档过粗，已改为 1 位以便划分）；
     底档特殊处理：降水等非负变量下界舍入为 0 时显示 **"0"**，避免出现物理无效的 "＜0"
     （温度可为负，保留 "＜-8.7"）。
     标签为**连续字符串、等宽字体（Consolas/monospace）、右对齐**——使 ≥ / ＜ / 区间
     文本的末尾数字在同一列垂直对齐（曾用 flex space-between 两端对齐，中间空隙过大已取消）；
     色带颜色不受影响（温度反转彩虹、降水原版彩虹）。
     注：档位边界由分位值等分算出，实例中个别边界（如 8.8 vs 8.7）差 0.1，
     因实例本身混用了向上取整与四舍五入，非格式问题。
   - **唯一功能性差异**：simulate 对 runoff 会把图例下界 clamp 到 0，本模块保留真实 minValue
     （温度含负、降水 0 透明，故 minValue 即真实分位下界），否则温度负温无法显示。
   - 图例最小档是**开区间"小于 xx"**（同 simulate 底档语义），并修掉"非零小值被四舍五入成 0"
     的问题（decimalPlaces 档宽自适应 + 非零下界自动提精度，如降水 0.003 → dp3 → "小于 0.003"）。
   - **渲染透明规则按变量区分**（功能性 bug 修复，非样式）：温度 0/负为合法值不透明，
     仅 NaN/-9999/≤-3e38 透明；降水 0=无降水才透明。否则冬季温度图负温/冰点会空白。

## 6. 已知风险与边界

1. **ERA5 单位换算的口径变更**：见 §4.3。在需求方明确"用原值还是换算值"前，**保留默认原值 + 新增 `unit` 字段**，前端展示做格式化但不做换算（避免擅自做决定）。
2. **`temperature_2m` 文件数 575 ≠ 365/366**：索引库可能混入历史日期或多源复本，前端按真实查询结果为准，不要预设"年内每天都有"。
3. **大栅格解码卡顿**：`loadGeoTiffLayer` 在主线程逐像素循环，637 万像元时明显卡（见文档 §6.4）。**不在本次方案范围**，仅在 UI 上用 `showLoading` 遮罩缓解。
4. **`interpolateColor`/`createLegend` 抽离的副作用**：simulate.js 是**单页面脚本**，未导出任何依赖 `loadGeoTiffLayer` 的全局状态；拆出后两个页面都能调用，但**变量 `isLoopPlaying`/`isLoadingTiff` 等仅在 simulate.js 内有效**，不需要同步。
5. **`calculate_mean=true` 性能**：单文件 575 个均会触发 575 次 `rasterio.open` + 读盘，串行大约 30~60s/请求（按 §4 文档 §2.4 单栅格尺寸外推）。**前端必须显式触发**，并在按钮上加 loading 状态。后续若要批量均值，按文档 §5"服务端 PNG 预渲染"思路迁移。
6. **依赖 air-datepicker**：本次方案不强制依赖 `<input type="date">` 替换（保持 `<input type="date">` 原生控件），若需要中文日历再引入 `date-picker.js`。
7. **跨页加载顺序**：HTML 中 `<script>` 是同步加载，新引入的 `geotiff-render.js` 必须放在 `geotiff.js` 之后、`main.js` 之后（因为要用 `window.map`）。新增 `meteo-query.js` 必须放在 `geotiff-render.js` 之后。
