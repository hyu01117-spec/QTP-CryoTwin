## 一、背景与任务目标

洪水灾害风险评估是数字孪生系统的核心业务模块，采用经典的 **Risk = H × E × V**（危险性 × 暴露度 × 脆弱性）框架，在栅格像元级计算综合风险，并以分位数相对分级（q20/q40/q60/q80）映射为 5 级成果。

本阶段任务聚焦两点：
1. **升级暴露度（E）维度**：将原"GDP + 人口"两维构造，扩展为 **GDP / 人口 / 耕地 / 粮食 / 牲畜** 五维等权合成，提升农业与民生暴露的刻画能力；
2. **补全前端展示界面**：实现完整、统一的结果呈现与交互逻辑，明确该类评估模块弹窗（模态框 / 提示框 / Toast）的标准信息结构，确保展示内容与弹出信息风格统一、语义清晰、贴合评估业务场景。

## 二、执行过程（关键步骤）

### 2.1 原始数据预处理（数据就绪）
- 清洗社会经济原始表（D1–D6 系列 xlsx），统一量纲（亿元→万元、万人→人），将宽表（年份×指标）逆透视；
- 县域名称规范化（去除行政后缀），建立别名映射 **合作市→夏河县**（经核验矢量库含夏河县、不含合作市）；
- 缺失年份就近取期；GDP 以历史序列（≤2015）+ 最新年（2020）合并取最新；
- 产出 8 个干净数据文件（GDP / 人口 / 耕地 / 粮食 / 牲畜最新值 CSV、长表、别名表、校验报告），校验匹配率 86.4%–89.7%，无真实数据损失。

### 2.2 后端 E 暴露度模型升级
- 在 `webgis_backend/modules/alert.py` 中重构暴露度计算：五维县域最新总值经 **IDW 插值**（k=8，power=2.0）空间化；
- 引入 **OSM landuse 像素调制**：居民地类（residential/industrial/commercial…）向人口与 GDP 集中，耕地类（farmland）向耕地与粮食集中；
- 统计层改为"淹没县域真实汇总值"（按质心落入淹没区者求和），避免插值面积分造成的量级失真；
- 返回值扩充：`total_arable_ha / total_grain_t / total_livestock_head / county_points_detail / exposure_osm_modulated` 及 `meta.exposure_dimensions`。

### 2.3 前端展示界面补全（统一弹窗标准）
- 引入 `css/components.css` 设计系统，统一 `statCard / badge / ring / btn / toast` 视觉语言；
- 重写结果模态框 `showRiskResultModal`，落地 **五段标准信息结构**（见第四节）；
- 新增地图左上角**持久概览面板**：分析后常驻显示等级、评分与核心指标，点击"查看完整评估结果"可重开模态框；
- Toast 统一改走 `UI` 组件库，消除此前两套提示样式不一致问题；
- CSV 导出扩展耕地 / 粮食 / 牲畜 / 各维匹配县域数 / OSM 调制标记。

## 三、采用的方法与技术方案

| 环节 | 方法 / 技术 |
|------|-------------|
| 风险建模 | H-E-V 乘法框架；栅格像元级运算；分位数相对分级（5 级） |
| 空间化 | 县域点总值 → IDW 反距离加权插值（k=8, p=2.0） |
| 细节增强 | OSM landuse 要素类做像素级权重调制（dasymetric 思想） |
| 统计口径 | 淹没县域质心落入法"真实汇总"，与相对分级解耦 |
| 前端框架 | 原生 JS + OpenLayers（图层渲染）+ ECharts（等级占比饼图） |
| 组件规范 | 统一 UI 组件库（暗色冰蓝主题）、模态框五段标准、Toast 统一 |

> **关键约束说明**：现有 `economy_counties.geojson` 为**点层**（2089 个县域质心，非面），OSM landuse 仅为**局部裁剪**（farmland 44 / residential 55 像素），尚不具备县域面 dasymetric 条件。故当前采用"IDW + OSM 像素调制"的稳健替代方案，并保留 `_dasymetric_distribute` 接口，待补充县域面图层与全域 OSM 后可无缝升级为真 dasymetric。

## 四、成果总结

1. **后端（alert.py）**：暴露度由二维升级为五维真实汇总合成，离线端到端验证通过，`py_compile` 语法校验通过，无悬空变量。
2. **前端（alert.html / alert.js）**：结果展示完整、风格统一。`node --check` 语法校验通过。
3. **统一弹窗标准（五段结构）**已固化于代码与注释，可直接复用于雪/冰/冻土等其余评估模块：
   - **① 评估结果概要**：一句话结论（主导等级、淹没面积、涉及资产/人口、评估范围）；
   - **② 评分 / 等级**：综合风险评分（面积加权 0–100）+ 等级徽章（1–5 级）；
   - **③ 关键指标数据**：淹没面积 + 五维暴露真实汇总（GDP / 人口 / 耕地 / 粮食 / 牲畜）；
   - **④ 风险提示与建议**：依据主导等级与暴露构成自动生成处置建议；
   - **⑤ 操作引导按钮**：前往灾害过程模拟 / 导出统计 / 下载 GeoTIFF / 保存图表。
4. **数据资产**：8 个干净文件落盘，配套校验报告，可复现、可溯源。

## 五、遇到的问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 真 dasymetric 不可行 | 县域矢量为点层、OSM 仅局部裁剪 | 改用 IDW + OSM 像素调制；保留面 dasymetric 接口待后续升级 |
| 别名方向错误 | 误判合作市/夏河县归属 | 核验矢量库后修正为"合作市→夏河县"，重跑后命中 |
| 字段 merge 失败（KeyError '_k'） | 点与面帧列名不一致 | 统一为 `_key` 列后合并 |
| 缺数据误评估 | 评估前未生成 flood_inundation | 后端返回结构化 409 + `NO_INUNDATION_DATA`，前端阻断式引导面板"前往灾害过程模拟" |
| 相对分级被误读为绝对风险 | 分位数法仅表征区内相对高低 | 前端显式标注"相对分级 / 真实汇总"，避免量级误读 |

## 六、汇报要点（口头快速传达）

- **做了什么**：把洪水风险评估的"暴露度"从 2 维扩到 5 维（新增耕地、粮食、牲畜），并补齐了完整、统一的前端结果展示。
- **怎么做的**：县域权威统计 + IDW 空间化 + OSM 像素调制；前端落地"概要—等级—指标—建议—引导"五段标准弹窗。
- **结果如何**：后端离线验证通过、前端语法校验通过；数据干净可溯源；风格与系统一致。
- **两点提醒**：① 受数据限制，当前为 IDW+调制方案，真 dasymetric 待补面图层后升级；② 正式演示前需启动后端服务跑一次完整链路（环境受限，本次仅做静态与离线验证）。
- **价值**：统一弹窗标准可一键复用到雪/冰/冻土等模块，降低后续前端成本。
