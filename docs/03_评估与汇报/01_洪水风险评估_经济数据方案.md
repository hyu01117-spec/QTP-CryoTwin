# 青藏高原洪水灾害风险评估：社会经济数据梳理与实施方案

> 数据范围：`data/raw/青藏高原社会经济数据/` 及既有 `data/raw/economy/GDP_data.csv`
> 评估框架：**Risk = 危险性(H) × 暴露度(E) × 脆弱性(V)**（UNDRR / IPCC AR5 / 第一次全国自然灾害综合风险普查 通用框架）
> 适用对象：县域尺度的洪水灾害风险评估（栅格像元级计算，县域汇总统计）

## 二、可用于评估的经济数据 vs 必需数据

### 2.1 必需数据（缺任一则评估不可进行）
- **人口（D3）**：暴露度的基本承灾体，所有规范均要求。缺人口则无法量化"多少人暴露"。
- **GDP / 经济体量（D1 或 D0）**：经济损失的核心度量，暴露度主指标。
- **社会经济脆弱性参数（D8 / SV_QTP）**：脆弱性 V 的主来源；现行模块已依赖其栅格化。
- **空间边界（县域面 + 评估区栅格）**：用于空间匹配与县域汇总。

> 上述四类为**最低可行集**。现行模块即由此构成（D0 + D3 + D8 + 危险性 H）。

### 2.2 强烈推荐（显著提升高原适用性）
- **耕地面积（D6）+ 粮食产量（D5）**：高原以农牧业为主，耕地/粮食是主要暴露与生计脆弱来源，弥补单纯 GDP 对农牧区表征不足的缺陷。
- **牲畜存栏/出栏（D4、D7）**：牧区核心资产，青藏高原洪水对牧业打击直接，是特色暴露维度。
- **经济安全指数结果（D2）/ 经济安全原始表（D1）**：直接提供"经济韧性/抗灾恢复力"综合度量，可用作 V 的校核或作为"暴露—韧性"二维展示。

### 2.3 可选（关键基础设施与精细承灾体）
- **水库/水坝（D9）**：既是暴露对象（溃坝连带淹没），也是潜在洪水放大源，建议作为专项图层而非并入综合 E。
- **能源站点（D10，尤其水电站）**：河道上的电站溃决/淹没风险高，单列为关键基础设施暴露。
- **OSM 道路/铁路/居民点（D11）**：路网中断、居民点淹没后果量化。
- **草地生产力（D12）/ 牲畜空间分布（D13）**：牧业暴露的栅格化代理，适合替代或补充县域牲畜点。

### 2.4 不建议直接作为主指标
- "与口岸距离""宗教场所数""中学在校生"等：属边境/社会结构特征，宜作为脆弱性辅助变量或背景图层，不直接进 E/V 主公式。

## 三、各类数据适用场景与使用方法

| 数据 | 适用场景 | 使用方法 |
|---|---|---|
| 人口 D3 | 任何洪水暴露量化、撤离人口估算 | 县域面属性 / 点 IDW 空间化；与淹没栅格交得出"淹没人口" |
| GDP D1/D0 | 直接经济损失、资产暴露 | 县域点 IDW 或县域面汇总；生成地均 GDP 栅格 |
| 耕地 D6 / 粮食 D5 | 农业损失、粮食安全 | 县域汇总或栅格化，作为"农业暴露"子维度 |
| 牲畜 D4/D7 | 牧业损失（高原特色） | 县域或栅格（D13）空间化，牧区权重提高 |
| 脆弱性 D8 | 社会脆弱性 V | 按评估年就近取期（2000/2005/2010/2015/2020），栅格化；缺失县用淹没区非零中位数填充（现行做法） |
| 经济安全 D2 | 韧性/综合脆弱性校核 | 作为 V 的替代或补充指数；或用于"高暴露—低韧性"重点区识别 |
| 水库/能源 D9/D10 | 关键基础设施专项风险 | 点/面与淹没栅格叠加，单列"基础设施受淹清单" |
| OSM D11 | 路网/居民点后果 | 矢量叠加统计"受淹道路里程、居民点数" |

**维度合成（暴露度 E）建议**：对农牧交错的高原，推荐多子维度等权/加权合成：
`E = w1·GDP_norm + w2·人口_norm + w3·耕地_norm + w4·牲畜_norm`（权重依子区农牧结构自适应；文档已承认等权为简化）。

## 四、数据预处理方案

### 4.1 清洗（Cleaning）
- **单位统一**：GDP 必须统一为同一量级（建议"万元"）。已发现 `GDP_data.csv` 德钦县行单位混用（2000 标"亿元"、其余明文但同为亿元），解析器需按整行推断（亿元×1e4 转万元），**该缺陷已在 alert.py 修复**（德钦 2015：24.6万元→245700万元）。D1 中 `GDP（亿元）`、`第二产业增加值（万元）` 等混用单位，入库前须逐列标注并换算。
- **字段重命名**：D3–D6 的宽表（`P1980…`、`SU1980…`、`G1980…`、`A1980…`）需"逆透视"为长表 `(县名, 年份, 指标, 值)`。
- **数值清洗**：去除 `"—"、空、异常 0`；D4 早期年份存在 NaN，标记而非置 0。

### 4.2 缺失值处理（Missing Value）
- **时间缺失**（如 D0 仅到 2015，评估 2024 滞后约 9 年）：采用**就近取期**（取评估年之前最近一期），并标注"外推"置信度；长期方案须补全近年统计。
- **县域缺失**（某县无某指标）：用**同子区（农牧区定义/地市）非零中位数**填充，或空间邻域插值；现行模块对 SV 缺失县即用"淹没区非零中位数填充"。
- **年份缺口**（D4 个别年 NaN）：线性插补或前后年平均。

### 4.3 格式统一（Format Unification）
- 全部表格统一为 `UTF-8 CSV`，长表结构：`[县名, 地市, 地区, 年份, 指标, 值, 单位]`。
- 坐标/几何统一为 **分析 CRS**：建议青藏高原采用 **Krasovsky_1940_Albers**（中央经线 105°E，双标准纬线 25°N/47°N，与 SV_QTP 一致），或研究区 UTM。需重投影：OSM/水库/能源 geojson（WGS84 EPSG:4326）、`economy_counties.geojson`（EPSG:3857）均须转到分析 CRS。
- 县域名称对齐：**已发现行政区划变更**——夏河县与合作市 1998 年分设/合并（D3–D6"数据说明"已记录）。须建立**名称映射表**（别名、历史名→现名）确保多年数据可串联。

### 4.4 空间匹配（Spatial Matching）
- **县域面 ↔ 点/栅格**：GDP/人口等县域属性挂接到县域面（`economy_counties.geojson` 或 SV_QTP 县域面），再栅格化到评估分辨率。
- **点 → 栅格（IDW）**：用于生成连续暴露面（k=8, power=2.0，现行参数）。注意 IDW 在高原稀疏站点下会高估边缘——建议叠加"县域面汇总"校核量级。
- **关键设施（D9/D10/D11）**：矢量与淹没栅格 `overlay` 叠加，直接统计受淹对象清单（不做 IDW）。
- **栅格代理（D12 草地、D13 牲畜）**：重采样到评估分辨率后直接作为牧业暴露栅格。

## 五、风险评估实现：完整技术思路与步骤

### 步骤 1 — 数据筛选（Data Screening）
1. 确定评估时段 `[start, end]` 与空间范围（全高原 / 指定流域）。
2. 按年匹配：人口(D3)、GDP(D1/D0)、耕地(D6)、粮食(D5)、牲畜(D4) 取 `≤评估年` 最近期；脆弱性(D8)取 5 期最近者。
3. 过滤评估区外县域；输出"县域属性长表 + 县域面"。

### 步骤 2 — 指标构建（Indicator Construction）
- **危险性 H**：由上游 `flood_inundation` 时段最大值归一化（栅格，已落地）。
- **暴露度 E**（栅格）：各子维度 min-max 归一化后合成
  `E = normalize(GDP) ⊕ normalize(人口) ⊕ normalize(耕地) ⊕ normalize(牲畜)`，仅在淹没区（H>0）赋值。
- **脆弱性 V**（栅格）：D8 指标综合为社会脆弱性指数（或复用 SV_QTP），归一化。
- 可选 **韧性 R_econ**：由 D2 经济安全得分反向作为"负脆弱性"参与展示。

### 步骤 3 — 风险计算（Risk Computation）
- 栅格像元级：`Risk = H × E × V`（与现行模块一致）。
- 非淹没区 Risk=0。

### 步骤 4 — 风险分级（Classification）
- **推荐**：相对分级（分位数 q20/q40/q60/q80 → 5 级），各级面积均衡，适合"区域内相对高低"区划（现行做法）。
- **规范对照**：叠加绝对后果阈值（如"淹没 GDP> X 万元 / 淹没人口> Y 人"）定义**极高/高/中/低**五级，用于决策时须注明绝对量级。
- 颜色与图例沿用 `#2c7bb6/#abd9e9/#ffffbf/#fdae61/#d7191c`（低→高）。

### 步骤 5 — 结果输出（Output）
- **栅格**：risk / hazard / exposure / vulnerability 四级 tif（已生成）。
- **统计**：按县域真实汇总（非 IDW 面积分，已在 alert.py 修复）——淹没总面积、淹没 GDP 总量（万元）、淹没人口、受淹耕地/牲畜、受淹关键设施清单、各等级面积与 GDP/人口占比。
- **前端**：结果面板标注"相对分级"与"真实汇总"语义（已落地）；无淹没数据时**阻断并引导先运行 simulate**（工作流串联已完成）。

## 六、规范符合性与可操作性要点

1. **框架合规**：R=H×E×V 与 UNDRR、IPCC AR5、《第一次全国自然灾害综合风险普查》承灾体—危险性—脆弱性框架一致。
2. **承灾体完整**：在必需"人口+GDP+脆弱性"基础上，补充耕地/牲畜/草地，契合青藏高原"农牧为主"的实际暴露结构。
3. **数据时效（待补）**：D0 仅至 2015、D1 仅 3 期，评估近年须补近年统计并标注外推；建议在数据说明中显式给出"数据基准年"与"外推标记"。
4. **量级可信**：县域汇总替代 IDW 面积分，避免暴露量失真（已修复）；关键设施用矢量叠加而非插值。
5. **可操作 pipeline**：县域长表 → CRS 统一 → 名称映射 → 栅格化 → 分维度归一化合成 → H×E×V → 分级 → 真实汇总统计 → 前端分级展示 + 上游串联引导。

> 注：本方案与现有 `webgis_backend/modules/alert.py`（`/api/alert/risk_assessment`）已落地的"GDP 单位修复、真实县域汇总、相对分级标注、simulate 工作流串联"完全衔接，可直接作为该模块的数据接入与指标扩展蓝图。
